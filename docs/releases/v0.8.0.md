# StorageScope v0.8.0 — Incremental Scans and Review Integrity

Released 2026-09-23. The downloadable app is for Apple Silicon Macs running macOS 14 or later. It is **ad hoc signed and has not been notarized by Apple**, as with v0.7.1. If macOS declines to open the DMG, you can [build from source](../../README.md#build-and-run) or wait for a notarized build. Intel Macs were not validated for this release.

## What changed

- Incremental rescanning reuses unchanged scan state, tracks changed directory subtrees, and falls back to a full walk when persisted state, event history, or scan settings cannot be trusted. A background full walk checks incremental results for divergence.
- Find Next and Find Previous navigate the displayed search scope. Navigation resets when the query, filter, view, or scan results change, and Folder Tree matches reveal their collapsed ancestors.
- Duplicate Review's All Sizes view includes smaller unverified same-size groups. Verification still separates SHA-256-confirmed copies from unverified candidates, and hard-link aliases do not count as duplicate copies.
- Trash review checks for candidates that disappeared before confirmation and reports them. A failed batch attempts to roll back all earlier moves, even if one restore fails.
- Duplicate hash-cache eviction now respects its byte bound, and persistence recreates a backing file removed outside the app. Regression tests cover changed files, cache reuse, and rollback outcomes.
- App Store packaging defaults to a release build. Bookmark diagnostics keep paths and path-bearing error descriptions private; notarization console output redacts supplied DMG and key-file paths.

## Validation and limits

The final local audit passed **251 tests across 26 suites**, including mocked release-script behavior, shell syntax, plist linting, and the public-file scan. An optimized release app build passed strict code-signature verification; its bundled version is 0.8.0 and the binary is arm64.

A synthetic duplicate-verification fixture contained **202.2 MB** of same-size candidates. A naive full-hash pass would read 202.2 MB; the optimized cold pass read **4.1 MB**, and a warm repeat using the **same process and cache instance** read **0 bytes**. These are fixture-specific byte measurements, not a general scan-speed or disk-reload claim. Disk-reload behavior has separate regression coverage.

Native UI smoke checks on a synthetic, redacted 25-item fixture confirmed Find Next selection, query-reset behavior, duplicate-group expansion, and Folder Tree ancestor reveal. Mixed missing-target sheet presentation, VoiceOver, Intel hardware, and the downloaded release binary were not exercised in that UI pass.

The screenshots currently in the README and website are **v0.7.1 interface references**, not captures of the v0.8.0 binary.
